# Design Review Checklist

用于实施、视觉审查和验收，按受影响范围选检查项，记录实际证据。

## 真实界面与视觉

- 启动实际目标界面；记录启动方式、版本、窗口/视口、DPI/缩放、主题与数据状态。用户截图是重要上下文，不能视为此次修改后的运行结果。
- 核对主次信息、视觉层级、对齐、密度、字体层级、间距、颜色、控件一致性及可读性；无明显视觉冲突、模板感、遮挡或 Overflow。
- 最小/默认/目标尺寸，长文字、中文/本项目语言、空列表与大数据量；检查截断、换行、滚动和可见操作。Web 按产品支持范围检查桌面与窄视口；原生桌面测试窗口 resize 和目标 DPI。
- 检查相关 Hover、Focus、Selected、Disabled、Loading、Empty、Error、Warning、Success 和重试/取消；错误位置及恢复操作明确，状态不只靠颜色。
- 键盘导航/焦点顺序/可见焦点、可访问名称、对比度与目标平台触控/鼠标尺寸；需要时检查屏幕阅读器。没有执行的无障碍测试写未执行，不能凭静态检查宣称完整合规。
- Web 观察实际 DOM/布局及 console、请求失败；截图人工检查，工具的 contrast/overflow 提示需确认影响。桌面检查真实窗口与宿主能力，离屏截图局限要说明。

## 功能与工程

- 对照改动前功能入口，确认按钮动作、数据输入、文件选择、导航/返回、弹窗、窗口、状态提示和核心交互仍正确；不得以隐藏入口替代设计。
- 受影响的业务输入输出与结果保持兼容；依变化执行项目现有测试/构建/类型检查。视觉快照不能替代功能验证，构建通过不能替代真实运行。
- 样式来自现有或新增的语义 Token/Theme，组件 Variant 和命名参数；可复用组件优先，允许有限且命名明确的装饰/平台参数，不为所有常量强建抽象。
- UI 更新无明显新卡顿；检查动画、Blur/透明/阴影、高频刷新、大表格、重渲染与 UI Thread Blocking 的实际影响。性能判断附可观察证据。

## 迭代与证据状态

采用“运行 → 观察/截图 → 检查 → 修复 → 再验证”。证据区分已通过、失败、未执行；明确界面、场景和尺寸，不把静态推断说成真实观察。

无法获取真实 GUI/浏览器画面时，原话说明“当前环境无法完成真实视觉验证”。完成静态及可运行检查，列缺失的视觉/交互场景；请用户后续提供实际截图以继续调整。不能因为期限近而写“视觉验证通过”。

完成标准：相关功能正确、结构清楚、设计一致、视觉层级/字体/间距/颜色/控件合理、交互状态完整、无明显 Layout Bug/Overflow 或视觉冲突，并具有与任务相称的实际验证。未满足的证据或风险必须出现在交付中。
