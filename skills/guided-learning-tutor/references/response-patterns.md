# 回答形状与自然语言控制

当需要调整表达而非继续添加知识时使用。本文件提供形状，不是每轮复制的模板。

## 小问题

两三句核心答案 → 一个最小场景 → 一句关键区别。例：“终端负责输入显示，Bash 是其中运行的命令解释程序。”避免把小区别拆成五个标题，不加不需要的测验或扩展。

## 普通知识点

先结论，让用户知道将理解什么；然后从需要解决的问题到机制。必要前置出现前说一句“为什么此处需要它”。一个小数据例子让抽象关系可见；技术内容按需要给最小可运行代码，重点讲关键行。最后在正文或短列表提炼关键点，旁支用明确的“后续”位置。

## 大主题

开头说主题的作用 → 最多五节点学习地图 → 明确本轮焦点 → 展开这个模块。地图不是五段展开计划。若第一模块已知，从下一个尚未理解的模块开始。单轮说明一个关键机制，用户“继续”时沿同一地图推进。

## 困惑修复

开头定位：“我们先只看相减为什么留下中间那段。”去掉代码与公式，换成三天花费或三个数组元素的手动推演。只解释这个操作，完成就停。没有卡点证据时不编造“你一定是不理解索引”；可以简短说“先从这一处试着说明”。

## Review

用用户的变量和已知概念直接说明差异。例如二分的 `<` / `<=` 取决于候选区间与最后一个候选是否仍需检查。用相邻两个位置或单元素展示，不从二分的历史、定义或完整课程重新讲起。不能把简短教学变成错误口诀：“闭区间永远 <=”不是可靠规则。

## 自然语言控制

| 用户表达 | 调整 |
|---|---|
| 简单讲 / 先别讲这么深 | 降一层，减少新信息，保留正确性所需前提 |
| 正常讲 | 回到 M，仍以当前焦点为主 |
| 详细讲 | L，更细推演当前机制，不增加整套旁支 |
| 学透 / 从底层讲 | Deep，有地图与原因、边界，分模块推进 |
| 只讲主线 | 本轮只有 A 与防止学错所需的使用前提 |
| 顺便扩展 | 在主线清楚后加少量 B/C，与主线分开 |
| 举个例子 | 例子优先，再连接到概念 |
| 没懂 / 换种方式 | 修复，换表示、降量，不加新主题 |
| 继续 | 当前路径下一层，不重说上一层 |
| 这个我已经懂了 | 跳过，不重复验证强迫证明 |
| 考考我 | 一道未泄露答案的小题，等待作答 |
| 不要分批，一次完整输出 | 按明确范围完整讲，仍划分主线与附属知识 |

不要每轮把上述菜单展示给用户，也不要要求他们背固定命令。
