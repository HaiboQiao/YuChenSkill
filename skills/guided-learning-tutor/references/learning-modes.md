# 教学模式与帮助程度

只有复杂切换、深入学习、提示分级或实操需要细节时读本文件。

## 选择帮助方式

缺前置 / 完全不会：Teach，先建立直觉和一个示范，不先要求凭空回答。知道部分但卡住：Guide，沿其真实尝试补一个缺口。已可应用且想练习：Practice，留给用户尝试。复习中已有知识：Review，只纠具体差异。

请求类型与帮助程度相互独立：Deep Learn 的零基础用户仍要先教；Practice 的用户缺少前置可以暂停题目，教一个相邻例子；Learn by Doing 可以对每一步的机制详细解释，但不要把后续所有操作一起塞来。

## Deep Learn

先地图，按是否已知选第一个未掌握的模块。单个模块可以走：问题动机 → 本质机制 → 一个推导或例子 → 一项会改变应用的边界 / 反例。不要把是什么、为什么、推导、边界、所有算法和测试各变成长章节。

按用户意愿进行复述：让用户先说已有理解，再补缺口；不是未学先答。追问为什么每次只到当前机制的下一层，不无限追问。验证用新情境中的解释、应用或反例；不是复述原句就认证学透。检查是邀请，用户选择继续讲、跳过、看答案或停止时尊重选择。

## Practice 与逐级 Hint

首次：只出一题，必要输入条件、样例输入输出和要完成的目标。解释样例如何满足题意可以，不能顺带讲解算法或关键更新步骤。

用户“给个提示”：当前轮 Hint 1，只指出有用的观察方向。再次卡住：下一轮 Hint 2，具体到关键关系。还卡住：下一轮 Hint 3，接近完整方法但保留实现机会。一轮一个提示，不能用折叠块或“别看后面的答案”变相泄露。

用户说“直接告诉我答案”：给示范和关键原因，不再强行提示。随后若要独立验证，换有意义的新情境；不能将看过解法的题当作独立完成。

用户解完要复盘：围绕其实际方法说清机制、关键前提和一个可迁移的模式；复杂度与可优化性分开。已有代码不完整或结果未知时，不假装测试全部通过。

## Learn by Doing

先定位操作环境，只问影响第一步的缺失信息。当前回复解释这一步要解决什么，给适用的命令和必要参数含义，指出成功信号及需要贴回的最小结果，然后停在这一步。

不要把未知输出当作成功，或者继续执行依赖它的步骤。出错则围绕真实错误解释和修复，不突然引入整套系统管理课程。仅示范的命令不自动执行；用户同时明确授权实际执行时，按授权与环境权限完成工作并提供必要解释，不故意暂停任务。

## Review / Diagnose

用户已知的主线不重讲。针对缺口给最小对照、反例或手动追踪；先明确结论，再解释使两种写法成立的不同前提。普通工作故障诊断没有学习目标时不触发本 Skill；“让我理解为什么出错”才加入教学。
