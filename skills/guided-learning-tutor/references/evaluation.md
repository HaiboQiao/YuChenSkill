# 行为验收方法

本文件用于开发、修改或评测 Skill，不在普通教学时加载。案例全集在 examples.md；它们是可检查的示例，不代表每次模型都会生成同样文本。

## 评分

每个实际回答按适用维度打 1–5 分，注明证据。不适用记 N/A，不能假装为满分。共同含义：1 明显失败；2 主要目标受损；3 基本可用但有明确问题；4 清楚正确且只有轻微不足；5 在此场景表现优秀。

| 维度 | 1 分表现 | 3 分表现 | 5 分表现 |
|---|---|---|---|
| Clarity | 看不出答案或解释无法理解 | 有结论，部分推理仍需猜 | 开头有答案，例子使机制可见 |
| Mainline | 变成无关课程 | 核心在，但旁支挤占正文 | 所有展开服务当前焦点 |
| Relevance | 新知识突然出现 | 有关联但部分理由不明 | 必要前置与转折都能追溯到问题 |
| Terminology | 多个未定义术语互相解释 | 少量新术语过密 | 普通话先解释，缩写及前提清楚 |
| Cognitive Load | 多模块多示例一起倾倒 | 基本可读但一次引入过多 | 一轮一个合适模块、新核心术语分散 |
| Verbosity | 长而重复或明显凑字 | 个别冗余 / 超预算 | 信息量合适，不以最短或字数为目的 |
| Completeness | 关键前置、公式条件或任务遗漏 | 核心完整但例子/条件不够 | 当前目标讲清，必要正确性前提齐全 |
| Progressive Disclosure | 所有相关知识立即展开 | 部分分层，仍越过当前模块 | 主线、简补与后续知识明确分开 |
| Adaptation | 重教已会内容 / 普通任务被劫持 | 大致选对模式，个别过问 | 根据已有基础和目标精准调整 |
| Recovery | 原样重讲、更长、更复杂 | 有简化但表示基本没换 | 明显降量、换表示、只修当前卡点 |

## 通过条件

核心十个案例的适用评分总平均至少 4/5。每个案例中适用的 Clarity、Mainline、Terminology，以及修复案例的 Recovery 都不得低于 4。下列情况直接不通过，不以其他高分抵消：教学事实错误；Practice 提前给解法或关键提示；大主题一次展开全部模块；修复反而更长；普通任务被强行改成教学；假称客户端发现或用户掌握。

## 实际评测流程

1. 无 Skill 条件下生成原始回答，保留失败证据，别根据目标规则改写基线。
2. 加载 SKILL.md，在相同场景生成真实答案。不要向生成助手提供参考答案或评分结果。只读当前模式确实需要的参考。
3. Case 5 承接同条件的 Case 2；Case 10 指定已理解累计求和。练习应加上用户请求 Hint 的连续轮次；实操应覆盖未知结果不能跳步。
4. 独立阅读和评分，保存完整答案、维度值和具体原因。字数和标题数只是线索，不能替代内容判断。
5. 对暴露的问题做窄修正；新上下文复测相同输入及反例。不要为了一个例子堆出更多通用禁止规则。
6. 对容易波动的“大主题 + 详细”至少做五个独立无 Skill 与五个带 Skill 样本，说明是否真正是全新上下文、模型和工具条件是否一致；不要把同一输出重复五次当五次采样。

把原始运行文件、失败、改动、复测和实际安装发现记录放开发项目 evaluation/，不要让普通学习读取所有测试输出。人工评分是行为质量检查，不等于受控用户学习实验，不能证明长期记忆效果或所有模型都遵守。
